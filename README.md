# SIS 3: reproducible orders service

Region: eu-north-1. Educational HTTP-only deployment, not production.
Prerequisites: AWS CLI credentials/role, Python 3.10+, Node.js 20+, npm,
Docker daemon, Git, permissions for CloudFormation/CDK bootstrap and resources.
No access keys in the repository. A restricted learner role may need instructor help.

## Architecture
HTTP -> ALB -> ECS Fargate -> SNS -> SQS -> Lambda -> DynamoDB.
SQS -> DLQ after maxReceiveCount=3. eventId is the idempotency key.
A conditional PutItem is the entire business effect: store one processed result.
No claims of exactly-once SNS delivery or external payment/email side effects.

## Deploy (from repository root)
```bash
bash scripts/deploy.sh sis3-dev
```
This installs local tools, bootstraps CDK if needed, synthesizes and tests templates,
deploys foundation, builds/pushes an immutable image, deploys app.
Review IAM changes at CDK approval prompts. No console resource creation needed.
Prefix is an environment input (3-25 lowercase letters/digits/hyphens).
AWS_REGION defaults to eu-north-1. Stack names are derived from prefix.

## Tests
```bash
bash scripts/check.sh sis3-dev
bash scripts/dlq-test.sh sis3-dev
```
Check consumer logs for processed and duplicate_skipped with the SAME eventId.
Observe poison message in DLQ, then send a normal order: processing must continue.
No fixed recovery-time assertion. Preserve actual timestamps and screenshots.

## Reproducibility
Commit and push this repository, including package-lock.json generated by setup.
From a clean clone, run `bash scripts/deploy.sh sis3-check`.
Run tests on both prefixes. Do not reuse resource names or copy ARNs manually.
Synthesized CloudFormation: cdk.out/<prefix>-foundation.template.json and
cdk.out/<prefix>-app.template.json. CDK source is app.py (at repository root).
These templates also reference Lambda assets: use CDK deployment, not template alone.
CDKToolkit bootstrap is shared account/region tooling, not part of either copy.

## Destroy (destructive, includes DynamoDB records and ECR images)
```bash
bash scripts/destroy.sh sis3-check
bash scripts/destroy.sh sis3-dev
```
App is destroyed before foundation because of cross-stack references.
Check remaining resources and Billing. CDKToolkit and bootstrap assets remain;
do not delete shared bootstrap used by other projects. Review separately.

## Cost/security limitations
One 0.25-vCPU/512-MiB Fargate task, public IPv4, public ALB, no NAT Gateway.
Task ingress on 8080 only from ALB. HTTP only; no authentication. Use synthetic data.
ALB, Fargate and IPv4 incur charges while running. No guaranteed Free Tier coverage.
Seven-day log retention. DynamoDB on-demand. Do not leave two copies running.
Base Python image is tagged, not digest-pinned; tags in project ECR are immutable.
The source-hash tag reuses an existing image; a new repository rebuild can differ
if the upstream base image changes. Pin base digest for byte-identical rebuilds.
